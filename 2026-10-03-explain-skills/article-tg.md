# Как разбираться в ответах ИИ: 4 формата вместо одного и 29 скилов, которые их закрывают

Сложность: средняя

![Джилл у доски, исчерканной схемами](https://raw.githubusercontent.com/NikolayGusev-astra/channel-materials/master/2026-10-03-explain-skills/images/cover.png)

Андрей Карпати 2 октября 2026 выложил разбор: как заставить модель объяснять понятнее. Он собрал три приёма: писать по стандарту упрощённого технического английского, сначала схема и интерактивная страница, потом объясняющее видео. От себя добавил четвёртый формат, который считает главным, и склеил всё в один скилл-диспетчер, чтобы не выбирать формат вручную каждую сессию.

Что из этого работает на практике и почему одного промпта мало.

## Проблема не в модели, а в формате

Модель отвечает примерно одинаково хорошо на вопросы "что такое X" и "как устроен протокол Y внутри". Разница между двумя ответами одного человека в том, что второй поставил в ответ диаграмму.

```
вопрос          формат ответа        сколько времени на понимание
"что такое X"   абзац текста         10 секунд, если повезло
"как устроен Y" схема                20 секунд, всегда
"что происходит" видео 90 секунд     90 секунд, зато без промахов
"что это значит" 3 абзаца подряд     непонятно, сколько это будет
```

Последняя строка и есть главная проблема. Ответ в четыре абзаца никогда не даёт понять, где кончилось объяснение. Читатель держит в голове весь текст, пока ищет вывод.

## Стандарт, который старше промптов

ASD-STE100 - это управляемый английский для авиационных механиков. Разработан в конце 1970-х по просьбе европейских авиалиний, первый документ AECMA вышел в 1985, а в январе 2025 стандарт стал международным.

Цифры из [Issue 9](https://www.asd-ste100.org/):

```
53 правила письма в 9 разделах
~900 одобренных слов, у каждого одно значение и одна часть речи
~1200 слов, которые использовать нельзя
```

Три правила, которые дают весь эффект:

```
"Open the file. Read line 3."              одна инструкция на предложение
"Remove the panel."  вместо "Take off..."  никаких фразовых глаголов
"<=20 слов" на инструкцию, "<=25" на описание
```

Словаря в открытом доступе нет: [ASD прямо запрещает его перепубликацию](https://en.wikipedia.org/wiki/Simplified_Technical_English), поэтому готовые скилы применяют структурные правила, а лексические - как направление, а не как проверку.

Один человек уже оформил это как скилл: [danyuchn/asd-ste100-skill](https://github.com/danyuchn/asd-ste100-skill), 3093 звезды, 176 форков, MIT. Задача у него специфическая - переписать так, чтобы агент не перепутал инструкцию при чтении. У меня он стоит рядом с линтером русского текста: английский словарь тут неприменим, поэтому для русских материалов работает другой набор правил.

Одно правило, которое надо понять до применения: модальность убирать нельзя. "Возможно, сбой произошёл из-за таймаута" и "сбой произошёл из-за таймаута" - это разные утверждения. Уверенность автора это содержание, а не стилистический мусор. Линтер это специально не проверяет.

## Видео как высшая ступень

Карпати считает объясняющее видео самым перспективным форматом. Пример с роликом про Shazam он приводит как иллюстрацию. Я проверил, что для этого нужно на этой машине, и результат оказался в две стороны.

Хорошая новость: движок стоит. Manim Community 0.20.1 в venv, разрешение 1920x1080, озвучка локальная через модель 0.3B. Актуальный релиз движка при этом 0.21.0, обновление я не трогал.

Плохая была: LaTeX на машине не было. Manim проверяет два бинаря, а не один, и второй - конвертер в SVG - в простой установке не появляется:

```
- Checking whether latex is available ... FAILED
- Checking whether dvisvgm is available ... SKIPPED
Manim cannot find <latex> on your system's PATH. You will not be able to use
Tex and MathTex mobjects in your scenes.
```

Формулы приходилось писать обычным текстом с юникодом: `Text("e^(iπ) + 1 = 0")` рендерится, `Text("∑ f(x) dx")` тоже, но дроби, интегралы со скобками и матрицы на этом не собираются в принципе.

Дальше - команды установки с нуля и грабли, которые на установку ушли.

## Как поставить LaTeX с нуля

Manim нужно два бинаря: `latex` - движок вёрстки, `dvisvgm` - конвертер результата в вектор для анимации. Без второго формулы не заработают даже при установленном первом.

Дистрибутив - MiKTeX. Выбор способа установки зависит от прав на машине:

```
scoop install miktex                      portable, без прав админа  <-- наш вариант
winget install MiKTeX.MiKTeX              есть, но просит UAC
TeX Live                                  в scoop нет пакета
```

Scoop-манифест ставит MiKTeX в portable-режиме с флагами `--unattended --private` и сам добавляет каталог с бинарями в PATH. На машине без прав админа это единственный вариант, который вообще завершается. Базовый инсталлятор весит 149 МБ.

Дальше - настройка, без которой агент зависнет намертво:

```bash
initexmf --set-config-value=[MPM]AutoInstall=1
```

По умолчанию MiKTeX на каждый недостающий пакет открывает диалоговое окно с вопросом "установить?". Для человека это нормально, для агента - тупик: ответа нет, а процесс висит. Ключ `[MPM]AutoInstall=1` переводит вопрос в автоматическое "да".

Отдельно про грабли: каноничная команда `miktex --set-default-package-install=1` на этой машине не отработала - висела дольше трёх минут и была прервана по таймауту. `initexmf` с тем же эффектом отработала за секунду и сразу выставила `AutoInstall=1` в `miktex.ini`. Проверяется одной строкой:

```bash
grep -i AutoInstall <путь-к-конфигу- MiKTeX>/miktex.ini
AutoInstall=1
```

## Проверка установки

Exit code рендера тут не годится: он скажет "ок" и на голом фоне. Нужен штатный диагност движка:

```bash
python -m manim checkhealth
```

Если Manim стоит в отдельном окружении, а не в системном Python, укажи его интерпретатор явно: путь к `python.exe` внутри venv, а не к скрипту в PATH.

Ждём четыре строки PASSED, включая обе ключевые. Если `dvisvgm` остался SKIPPED при зелёном `latex`, доустанавливается отдельно: `mpm --install=dvisvgm`. Флаг `--admin` в портативной установке не работает и вызовет отказ, поэтому указывать его не надо.

## Что изменилось после установки

Тесты на 1080p60: формула Эйлера, интеграл с пределами и матрица 2x2 с круглыми скобками. Всё три рендерится настоящим TeX:

```
MathTex(r"e^{i\pi} + 1 = 0")
MathTex(r"\int_a^b f(x)\,dx = F(b) - F(a)")
MathTex(r"\begin{pmatrix} 1 & 2 \\ 3 & 4 \end{pmatrix}")
```

![Джилл у монитора с анимацией синусоиды](https://raw.githubusercontent.com/NikolayGusev-astra/channel-materials/master/2026-10-03-explain-skills/images/video-curve.png)

Матрица до установки собиралась вручную из `Text` и рамки `SurroundingRectangle` - восемь строк кода, и скобки всё равно отставали от рамки. После установки это одна строка, и выглядит как надо.

Что не поменялось: кириллица в обычном `Text` работала и раньше, а вот русский текст внутри `MathTex` зависит от шрифта и настроек движка, я его не проверял. Подписи держи в `Text`.

Семь сцен из рецептов отрендерил и просмотрел кадрами: синус с бегунком, окружность на числовой плоскости, комплексная плоскость, бинарный поиск, сортировка, граф, матрица. По дороге вылезли две грабли, которые нигде не документированы: класс сцены нельзя называть так же, как импорт из движка (перекроет его и сломает вызов), а угол в версии 0.20 принимает объекты-линии, а не координаты.

## Что получилось у меня

Скилл-диспетчер `teachme` с лестницей форматов. Он не содержит правил форматов, только маршрутизацию:

```
ступень 1  текст    asd-ste100, humanizer-ru, pstack-teach
ступень 2  схема    eli5, docs-canvas, case-map-html
ступень 3  видео    explainer-video-3b1b, faceless-explainer
ступень 4  курс     course-program-design, course-authoring
```

29 скилов в отчуждаемой копии, 8 МБ, каждый со своей папкой. Копия нужна для переноса на другую машину и для страховки от куратора: фоновый процесс архивирует то, чем давно не пользовались, и новый скилы без пометки попадают в его зону.

Правило, которое оказалось важнее таблицы: начинать с дешёвой ступени. Схема делается за один вызов, видео в стиле 3b1b - это сорок-восемьдесят минут работы и шесть шагов с проверками. Если мысль не рисуется картинкой, упрощай, пока не нарисуется, и не лезь в видео.

## Три примера применения

Учёба. Курс по новой теме: сначала схема устройства подсистемы, потом ролик с объяснением одного механизма, потом практикум. Текстовый конспект на 40 страниц читается хуже, чем одна страница с пятью схемами и ролик на две минуты. Скиллы `teaching/course-program-design` и `teachme` закрывают обе задачи: первый планирует программу, второй разбирает, что не понялось.

Рабочие материалы. Инструкция из 12 шагов, написанная одним абзацем, читается медленно и с потерями. Тот же текст после прохода по STE-правилам: один шаг на строку, активный залог, конкретный исполнитель у каждого действия. Для регламентов, чек-листов и описаний настройки это даёт выигрыш без изменения сути. Отдельно ловятся маркетинговые прилагательные: "надёжный", "гибкий", "масштабируемый" в инструкции не значат ничего, пока не стоит рядом измерение.

Погружение в новый проект. Тут порядок обратный. Сначала скилл-обзор: что за код, какие сущности, где вход. Потом схема потока данных по главному сценарию, потому что текстом структуру чужого репозитория не разобрать. Видео тут нужно ровно в одном месте, где логика неочевидна: как собирается приложение, почему здесь выбран именно этот алгоритм. Ролик на такое объяснение экономит час перечитывания.

## Сколько это стоит

Схема: один вызов, минута. Ролик в стиле 3b1b на две минуты с озвучкой: 40-80 минут. Учебный курс с практикумами: дни, но он собирается из кусков, каждый из которых проходит через те же форматы.

Отдельно про проверку результата. Exit code рендера не доказывает, что кадр правильный: за время в прогоне у меня нашёлся обрезанный текст в схеме и сцена 3b1b, которая падала три прогона подряд. Проверяются кадры, а не код выхода. Для видео это обязательный шаг, для схемы - прогон через браузер с вопросом про переполнение.

## Когда это не нужно

Если задача простая и укладывается в два абзаца, формат не нужен. Если тема знакомая и ответ на вопрос - одно слово, лестница форматов только отнимает время. Видео для аудитории, которая не будет его досматривать, - трата часов.

Ну и главное ограничение: ни один формат не делает слабый ответ сильным. Переписанный по STE текст остаётся пустым, если в исходнике не было содержания. Формат чинит подачу, а не мысль.

## Что лежит в репозитории

К материалу прилагается отчуждаемая копия скилов диспетчера `teachme` - 29 папок со `SKILL.md`, 8 МБ, симлинки разыменованы. Копия нужна для переноса на другую машину и для страховки от куратора: фоновый процесс архивирует то, чем давно не пользовались.

Разворачивание целиком с нуля:

```bash
# 1. скопировать materials/teachme-bundle/skills в каталог скиллов
# 2. пересчитать реестр команд
/reload-skills

# 3. проверить, что всё на месте
find skills -name SKILL.md | wc -l        # ожидается 29
hermes skills list | grep -E "teachme|eli5|asd-ste100|3b1b"
```

Без `/reload-skills` имя не появится в автоподсказке: реестр команд кэшируется при старте сессии. Сам файл при этом виден - скиллы читаются с диска напрямую.

Для видео ещё один шаг, без него ролики с формулами не соберутся. Скрипт `materials/scripts/setup-latex.sh` делает это целиком и идемпотентно:

```bash
bash materials/scripts/setup-latex.sh
```

Что проверить первым: возьмите любой свой текст на полстраницы и прогоните его через схему. Разница между "прочитал" и "понял" обычно видна сразу.
