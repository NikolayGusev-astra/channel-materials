# Cloudflare для агентов, часть 1: каждый агент - микросервер

Cloudflare за два Agents Week (апрель и август 2026) собрала полный стек для агентов, и первая его часть - вычисления и наблюдаемость. Главная идея проста и непривычна: агент - не функция на сервере, а персистентный микросервер, по одному на пользователя.

## Почему не контейнеры

Классическое приложение обслуживает много пользователей из одного инстанса. Агент - наоборот: у каждого свой контекст, свои файлы, своя история. Сто миллионов сотрудников с личными ассистентами - это десятки миллионов одновременных сессий. Контейнеры по такой математике не сходятся: простой стоит денег, а агенты простаивают большую часть времени.

Решение Cloudflare - Durable Objects: каждый агент получает собственный изолят с встроенным SQLite, WebSocket-соединением, планировщиком и hibernation. Изолят спит, когда агент не работает, просыпается по событию и стоит около нуля. Это не скоуп-крип - Agents SDK давно GA, на нём работают продакшн-сервисы.

## Project Think: примитивы для долгоживущих агентов

В августе SDK пополнился набором примитивов под длинные задачи. Fibers дают durable execution: чекпоинты, восстановление после падения, автоматический keepalive - задача агента переживает рестарт воркера. Sub-agents - изолированные дочерние агенты со своей SQLite и типизированным RPC, чтобы главный агент не тащил весь контекст в одном окне. Persistent sessions хранят переписку деревом: форк ветки, компакция старых ходов, полнотекстовый поиск по истории.

Отдельно - песочницы для кода. Агент пишет и исполняет код в Dynamic Workers с рантайм-резолвом npm-пакетов, и это самое честное воплощение идеи code is the universal medium of action: не двадцать JSON-тулз на каждый чих, а код, который вызывает всё что нужно. Лестница исполнений от workspace-файлов до полного браузера позволяет выбирать цену шага.

## Наблюдаемость: tracing и его цена

Без трассировки агент - чёрный ящик. Cloudflare добавила агентные спаны в Workers tracing: видно каждый вызов модели, запуск тула, запрос одобрения у человека, расход токенов по сессии. Session replay проигрывает диалог по ходам, waterfall показывает, что и сколько длилось.

Пока бесплатно, но дата проставлена: с 1 октября 2026 каждый спан становится платным observability-событием по тарифам Workers Observability. И два нюанса, которые почему-то не в заголовках: лимиты на обрезку больших payload (часть событий пишется усечённой) и неровные дефолты записи содержимого - у одних полей запись включена по умолчанию, у других нет. Перед продом стоит явно настроить, что пишется, иначе узнаете об этом по странному пустому replay.

## @cloudflare/computer: рабочее место агента

Третий блок - open-source проект, дающий агенту постоянное рабочее пространство, которое мигрирует по лестнице исполнений: лёгкий V8-изолят для быстрых операций, Linux-контейнер для тяжёлых, браузер для сайтов. Файловая система и состояние переезжают вместе с агентом. Это ответ на главный минус локальных кодинг-агентов: они привязаны к ноутбуку, а их рабочее место здесь живёт в облаке и переживает отключение клиента.

## Что с этим делать

Стек интересен не фичами по отдельности, а формой: Cloudflare продаёт не "хостинг для LLM-приложения", а место, где агент - первоклассный житель с состоянием, памятью, деньгами и наблюдаемостью. Если ваш агент держит состояние в трёх базах и двух очередях, посмотрите, сколько из этого схлопывается в один Durable Object. Если не считаете спаны - считайте: с октября они в счёте.

Во второй части - деньги: кошельки для агентов, протокол x402 и почему Cloudflare выпускает стейблкоин.
