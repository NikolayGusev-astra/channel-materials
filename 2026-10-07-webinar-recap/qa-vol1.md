## Как искать скиллы (Запекан К.А., 00:43)

Три пути.

Skills Hub, каталог, встроенный в Hermes:

```
hermes skills search docker        # поиск по всем реестрам
hermes skills browse               # каталог целиком, с пагинацией
hermes skills inspect <id>         # превью SKILL.md без установки
hermes skills install <id>         # установка
hermes skills list                 # что стоит в профиле
```

В хабе больше 100 тысяч скиллов из десятка с лишним реестров. Фильтр по источнику отсекает шум: `hermes skills search terraform --source official` ищет только по официальным скиллам Nous Research.

Статья про устройство скиллов: https://hermes-agent.ru/news/explain-skills-ladder/, там про то, как агент сам создаёт скиллы из опыта и почему это его процедурная память.

Проверенный список: в файле `vendor-skills.md` рядом лежит джентльменский набор с командами установки. Все идентификаторы проверены живым хабом, не скопированы из постов.

## Диспетчер скиллов самописный? (Alexey Tolstenok, 00:45)

Нет. Диспетчер это встроенная механика Hermes: описание скилла лежит в SKILL.md с frontmatter, где указано имя и когда скилл применять. Агент читает описания и сам решает, какой скилл загрузить под задачу. Внешнего роутера нет: выбор происходит внутри контекста агента перед ответом.

Самописным бывает другое: сами скиллы. Вендорский скилл знает доку продукта, ваш личный знает ваши конвенции, ваши гейты и ваши грабли. Вторые со временем ценнее первых.

## MCP или tools: когда что (Alex P, 01:57)

Коротко: tools это встроенный слой, MCP это протокол подключения внешнего.

Tools уже внутри агента: файлы, терминал, браузер, поиск, память. Работают из коробки, конфигурируются в config.yaml, не требуют отдельного процесса.

MCP это протокол, через который агент подключается к внешним серверам: Jira, Confluence, базы, корпоративные API, что угодно со своим сервером. MCP-сервер это отдельный процесс, агент ходит в него по списку его тулов.

Правило выбора:

- задача решается локальными возможностями агента: tools, ничего подключать не надо;
- нужен доступ к внешней системе с её API: ищите готовый MCP-сервер;
- готового нет, а система важная: пишите свой MCP-сервер, это пара сотен строк.

Нюанс из практики: MCP расширяет контекст списком тулов, и каждый тул ест токены даже когда не используется. Подключайте только то, что реально нужно задаче. В Hermes тулы MCP-сервера можно фильтровать при настройке.
