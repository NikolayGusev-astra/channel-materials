# Omen Alpha fingerprint - материалы к статье "На opencode раздают GLM-5.5?"

Набор для повторения A/B-деанонимизации стелс-модели `omen-alpha` на OpenCode Go
методом сравнения метаданных с эталонной моделью (по умолчанию `glm-5.3-flash`).

## Что проверяется

1. **Формат идентификаторов ответа.** Стелс-модель отдаёт `id` вида
   `2026091222195714b8c29e10384477` (дата-время + hex, формат внутреннего API Zhipu/BigModel),
   эталонная GLM-5.3-Flash - обычный `chatcmpl-...`.
2. **Идентичность токенизатора.** Одинаковые фрагменты на пяти письменностях;
   константная дельта `prompt_tokens` означает один токенизатор
   (у стелс-модели дельта - это системный промпт релея, у нас она была -24).
3. **Самоидентификация под прямым вопросом** и ответ relay-обкладки.

## Запуск

Нужна подписка OpenCode Go и API-ключ:

```bash
export OPENCODE_GO_API_KEY=...
python scripts/omen_fingerprint.py --model omen-alpha --reference glm-5.3-flash
```

Отчёт пишется в `fingerprint_report.json` с вердиктом.

## Данные живого прогона 2026-09-12

- `data/ab_results.json` - сырые ответы 8 диагностических проб по обеим моделям
  (temperature 0, reasoning effort low, единый релей).
- `data/tokenizer_delta.json` - счётчики входных токенов на пяти письменностях:
  дельта константна (-24) на всех фрагментах => токенизаторы идентичны,
  разница лежит в системном промпте релея.

Ключевые наблюдения прогона: у omen-alpha в части вызовов `id` в формате
Zhipu BigModel, у glm-5.3-flash - всегда `chatcmpl-*`; стиль рассуждения
семейный (одинаковые речевые конструкции), но стелс-модель короче и без
двойной самопроверки; на прямой вопрос о вендоре отвечает UNKNOWN.

## Интерпретация

Один токенизатор + идентификаторы формата Zhipu + GLM-стиль рассуждения =>
наиболее правдоподобно: глубокий пост-трейн семейства GLM, совпадающий с
пропавшей из нумерации Z.ai версией 5.5 (не подтверждено ни Z.ai, ни OpenCode).
Подробности - в статье.
