# REA в Hermes: методика реверс-инжиниринга промокод-валидатора

Методика и харнессы к статье о [REA (Reverse Engineer Anything)](https://github.com/morluto/rea)
в связке с агентом Hermes. Демо показывает полный цикл: скомпилированный
артефакт - evidence от REA - слепая пере-реализация агентом - доказательство
эквивалентности на 10 000 случайных входов и полном переборе префиксов.

Замечание о правовых границах: таргет демо написан автором статьи специально
для этого разбора. Вскрывать можно только своё или то, на что есть явное
разрешение владельца.

## Замеренные числа (Windows, REA 6.8.0, Node 24.22.1)

- Бандл жертвы после минификации: 645 байт.
- Evidence после `rea analyze`: 288 866 байт, 2,6 с.
- Слепое восстановление отдельным агентом: 11 обращений к модели, ~3 минуты.
- Проверка: перебор всех 1 048 576 префиксов и 10 000 случайных строк,
  включая мусор вне алфавита. Расхождений: 0.

## Состав

```
harness/promo-app-src/   исходник жертвы (для сборки своего бандла)
harness/promo-app-built/ собранный минифицированный бандл (артефакт "магазина")
harness/rebuild/         чистая пере-реализация, восстановленная агентом
harness/diff-test/       дифференциальный тест оригинал против пере-реализации
docs/hermes-setup.md     мануал по установке REA в Hermes Agent (Windows)
```

## Воспроизведение

Требования: Node.js 22.23.4+, 24.22.1+ или 26.12.1+; глобальный пакет
`rea-agents` (`npm install -g rea-agents`); Java 17+ только для Android-таргетов.

1. Собрать жертву (или взять готовый бандл из `harness/promo-app-built/`):

   ```bash
   npx esbuild promo-app-src/index.js --bundle --minify --platform=node \
     --outfile=promo-app-built/main.js
   ```

2. Снять evidence:

   ```bash
   rea analyze ./promo-app-built --json > evidence.json
   ```

3. Отдать бандл с evidence агенту-восстановителю с запретом читать исходники;
   попросить описать алгоритм словами и написать чистую пере-реализацию.
   Эталонный результат восстановления - `harness/rebuild/rebuild.js`.

4. Сверить на дифференциальном тесте:

   ```bash
   node harness/diff-test/diff_test.cjs harness/rebuild/rebuild.js 10000
   ```

   Ожидаемый вывод: `"mismatch": 0` и распределение скидок по валидным кодам.

## Ключевые параметры восстановления (для сверки)

- Алфавит: 32 символа, без I, O, 0, 1.
- Формат: две группы по 4 символа через дефис, вход нормализуется
  (обрезка пробелов, верхний регистр).
- Контрольный символ: накопление `acc = acc*3 + вес(символ)*(позиция+1)`
  по модулю 31 по первым семи символам; вес символа - индекс в алфавите.
- Скидка: только по префиксу - накопление `acc = acc*31 + вес(символ)`
  в младших 32 битах, затем таблица `[10, 10, 15, 10, 20, 15, 10]`
  по остатку от деления на 7.
- Занятная деталь: буквы I и O проходят проверку формата, но гарантированно
  валятся на контрольной сумме.
