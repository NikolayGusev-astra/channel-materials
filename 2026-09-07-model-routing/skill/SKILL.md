# model-routing — выбор модели по способностям под задачу

Принцип: модель выбирается по тому, ЧТО она умеет (бенчи, контекст,
модальности, tools), а не по факту бесплатности. Бесплатная модель с 1%
terminal-bench хуже платной с 70%. Цена — второй фильтр после пригодности.

## 1. Реестр провайдеров (живой источник, обновлять еженедельно)

Реестр **не хранится в этом скилле** — он устаревает быстрее, чем обновляется текст. Перед каждым делегированием, использующим free-пул, прогоняй три команды (раздел 8) и смотри живой список. Ниже — инвариантная часть, не меняется:

| Категория | Провайдер | Free-предложение | Лимиты free | Как проверить живьём |
|---|---|---|---|---|
| **Прямой вызов (мгновенно, моими инструментами)** | **OpenRouter** | 18 моделей `:free` (пул вращается) | ~20 req/min + дневной кап | `GET openrouter.ai/api/v1/models`, фильтр `:free` |
| **Прямой вызов** | **Nous Portal** | каталог 41 модель; free-тир = подписка $0, только free-модели, 50 RPM / 500K TPM | бесплатный список определяется живой ценой портала (`partition_nous_models_by_tier`), НЕ манифестом | catalog: `hermes-agent.nousresearch.com/docs/api/model-catalog.json` |
| **Прямой вызов** | **Kilo AI** | ~15 моделей free (тот же OpenRouter-пул + свои) | свои квоты; **живой terminal-bench** в полях `benchmarks.kiloBench.terminal-bench.overallScore` | `GET kilo.ai/api/models` (поля priceInput/priceOutput) |
| **Субагент-делегация (минуты, свой токен-пул)** | **codex** (GPT Plus) | нет free; `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna` | дневной кап аккаунта; `chatgpt.com/backend-api` может быть egress-блокирован (отдельный диагноз!) | `codex exec -m <model> ...` через `delegate_task` / прямой вызов, `--sandbox danger-full-access` обязателен на Windows |
| **Субагент-делегация** | **zcode** (Z.AI plan) | нет free; `glm-5.3`, `glm-5.2`, `glm-5-turbo` (конфиг `~/.zcode/cli/config.json`) | скользящее окно подписки; `--model` флага НЕТ, модель только через config.json | `node zcode.cjs -p ...` через `delegate_task`; ОБЯЗАТЕЛЬНО `pty=true` (без TTY молча ничего не делает) |

⚠️ **codex и zcode — НЕ провайдеры для моего прямого вызова.** Это субагент-делегация
через `delegate_task` (или прямой вызов `codex exec` / `node zcode.cjs`). Они жгут
СВОЙ токен-пул, выполняются минутами, требуют `pty=true` для zcode. Любой
"прыжок" между codex/zcode — это новый запуск субагента, не переключение модели
внутри одного процесса. "Цепочка" для категории = **либо делегировать субагенту
(выбрать кого), либо остаться в себе (прямой free)**.

⚠️ Категории «nous/free» НЕ СУЩЕСТВУЕТ. У каждого провайдера — конкретный
список моделей, отдаваемых бесплатно, со своими лимитами. Пересечение пулов
OpenRouter/Kilo/Nous велико (каталог Nous питается OpenRouter), но лимиты у
всех СВОИ: одна и та же free-модель через разных провайдеров = разные квоты.

## 2. Способности free-моделей (terminal-bench kilo, 445 trials, 2026-09)

Kilo гоняет свой terminal-bench на живых моделях — единственный
стандартизированный источник по всем сразу. Топ free-применимого:

| Модель | ctx | tb (kilo) | Для чего годится | Не годится |
|---|---|---|---|---|
| `tencent/hy3` | 256K | **47.6%** | код, агентные прогоны, general — ЛУЧШАЯ free | нет мультимодальности |
| `minimax/minimax-m3` | 1M | 47.6% (платн. замер) | длинный контекст, мультимодальная (text+img+video), long-horizon агенты | глубокий релизинг-режим |
| `poolside/laguna-s-2.1` | 256K | 31.0% | чистый кодинг (vendor: 70.2% TB2.1 — другая версия бенча!), код-агент | общие задачи, проза |
| `nvidia/nemotron-3-ultra-550b` | 1M | 19.1% | orchestration длинных агентных пайплайнов, 1M контекст; НЕ для кода | код (слаб!), точные фиксы |
| `nvidia/nemotron-3-super-120b` | 256K | 15.5% | high-throughput рутина, классификация | сложный код |
| `google/gemma-4-31b-it` | 256K | — | мультимодальная (img+text), проза, переводы | агентный код, tools |
| `cohere/north-mini-code` | 256K | — | лёгкий агентный код (30B/3B MoE) | тяжёлые фиксы |
| `thinkingmachines/inkling` | 1M | 43.6% (платн.) | general reasoning, tools, мультимодальная | — |
| `poolside/laguna-xs-2.1` | 256K | 26.7% | мелкий код-рутин | сложные задачи |
| `inclusionai/ling-3.0-flash` | 256K | — | быстрая рутина | — |
| `baidu/cobuddy` | ? | 1.1% | НЕ ИСПОЛЬЗОВАТЬ для задач | всё |

Контекстный масштаб для калибровки: платные лиды того же бенча —
gpt-6-astra 79.3%, gpt-5.6-sol 76.2%, gemini-3.8-flash 75.3%,
z-ai/glm-5.2 53.0%. То есть лучшая free (hy3 47.6%) дотягивается до
уровня glm-5.2/minimax-m3-платной, но НЕ до frontier.

Vendor-заявления (70.2% у laguna) ≠ независимый замер: kilo меряет свою
версию terminal-bench на своём харнессе — цифры между бенчами несопоставимы,
сравнивай только внутри одного источника.

## 3. Выбор по способностям: правило трёх фильтров

Перед выбором модели отвечь на три вопроса в порядке приоритета:

1. **Требования задачи.** Нужны ли: tools/agentic (→ только models with
   tools: true), мультимодальность (→ minimax-m3, gemma-4, inkling, dots-3),
   гигантский контекст >256K (→ nemotron-ultra, minimax-m3, inkling: 1M),
   глубокий код (→ hy3, laguna-s, north-mini-code; НЕ nemotron-ultra).
2. **Способности из реестра** (раздел 2). Модель с tb < 15% не берётся для
   содержательных задач никогда, какой бы бесплатной ни была.
3. **Цена/лимиты.** Только среди прошедших фильтры 1–2 выбираем самое
   дешёвое/бесплатное. Бесплатность без пригодности = сжигание времени.

Примеры применения:
- «почини race в трёх модулях» → нужен код+tools → hy3 (free) есть; нет — zcode/glm-5.3
- «проанализируй лог на 400K строк» → нужен контекст 1M → minimax-m3 или nemotron-ultra (если не код)
- «найди котиков на 200 картинках» → нужна мультимодальность → gemma-4-31b (free)
- «напиши пост в телеграм» → проза, код не нужен → любая; первыми бесплатные

## 4. Скоринг запроса (детерминированный, без LLM)

| Сигнал | Вес | Триггеры |
|---|---|---|
| `subtasks_many` | +4 | «разбей», план из 3+ задач |
| `exhaustive_search` | +4 | «найди все», «все usages» |
| `architecture_keywords` | +3 | архитектура, ADR, миграция схемы |
| `impact_system_wide` | +3 | прод, весь пайплайн |
| `risk_keywords` | +2 | безопасность, необратимо |
| `debugging_keywords` | +2 | «падает», race, утечка |
| `fanout_intent` | +2 | «распараллель», fan-out |
| `cross_file` | +2 | правки в 3+ файлах |
| `message_length` | +1/+2 | длинный запрос |
| `routed_skill_class` | +1/+2 | через аудит-скиллы |
| `simple_request` | −2 | «переименуй», однострочник |

Пороги: **0–2 quick · 3–5 standard · 6–9 deep · 10+ architect/ultrabrain**.

## 5. Цепочки (по способностям + диверсификация)

**Ключевая правка:** codex и zcode — субагент-делегация, не провайдеры для прямого
вызова. "Цепочка" для категории = **либо делегировать субагенту, либо остаться в себе
на free-модели**. "Прыжок на звено 2" при недоступе субагента = новый `delegate_task`
(минуты ожидания), не "переключение модели в текущем вызове".

| Категория | Цепочка | Логика |
|---|---|---|
| **quick** | `kilo:ling-3.0-flash:free` (мой прямой) | субагент невыгоден: 5 мин сетапа ради 1 ответа |
| **standard** | `kilo:tencent/hy3:free` (мой прямой) → `delegate zcode/glm-5.3` (если не хватит) | free на первый круг, эскалация на субагента при слабом результате |
| **deep** | `kilo:tencent/hy3:free` → `delegate zcode/glm-5.3` → `delegate codex/gpt-5.6-terra` | лестница: бесплатно → подписочный субагент → платный субагент. Каждая эскалация — явное решение, не автоперебор |
| **architect** | `delegate zcode/glm-5.3` → `delegate codex/gpt-5.6-sol` | free не дотягивает (47% < потребных 70%+), стартуем с субагента |
| **writing** | `kilo:gemma-4-26b:free` (мой прямой) | проза/переводы — бесплатных хватает, субагент невыгоден |
| **мультимодальная** | `kilo:minimax-m3:free` (мой прямой, 1M ctx, mm) → `delegate codex/gpt-5.6-sol` | mm через прямой free; эскалация только если не хватит |
| **контекст >256K** | `kilo:minimax-m3:free` (1M ctx) → `delegate codex/gpt-5.6-sol` (1M ctx) | оба с миллионным контекстом, начинаем с free |
| **ultrabrain** | `delegate codex/gpt-5.6-sol` (xhigh) → спросить юзера | здесь free точно не справится |

**Правила переключения:**
1. **codex недоступен по ЛЮБОЙ причине** (egress-блок chatgpt.com, кап аккаунта,
   1311 model-restriction) → не ретрай codex-модель, переходи к zcode/free.
   Скилл различает: "usage limit" = кап, "reconnect 5/5" + chatgpt.com 000 = egress.
2. **codex/zcode 429 в подписке** = субагент мёртв на сегодня, остаёмся в себе на
   free-модели или поднимаем уровень задачи юзеру.
3. **429 на free-модели** → другая free-модель, не ретрай той же. Если целый
   провайдер лежит (openrouter 502) → kilo:та-модель, если есть.
4. **≤2 запусков субагентов подряд** (стоимость старта + лимиты).
5. **Эскалация только при явных флагах**: код галлюцинирует, не хватает фактуры,
   юзер сказал «глубже». Не «на всякий случай».
6. Явное указание юзера перекрывает скоринг.
5. Каждое переключение — в лог.

## 6. Точка интеграции

- Перед `delegate_task` (codex/zcode) или моим прямым вызовом: скоринг →
  категория → способность (раздел 3) → голова цепочки.
- Специфика скиллов: /cursor аудиты требуют strong-coding моделей — free-звено
  брать только hy3/laguna, не nemotron.
- Скоринг в голове, без субагентов.

## 7. Лог маршрутов

`~/.hermes/model-routing-log.jsonl`:
`{"ts":"...","task_class":"deep","mode":"direct|subagent","provider":"kilo","model":"tencent/hy3:free","outcome":"ok|escalated","next_provider":"codex/gpt-5.6-terra"}`
Недельный ритуал: доля sol/terra должна падать; free-звенья должны решать
свои классы без эскалации; количество `escalated` записей = сколько раз free не хватило.

## 8. Обновление реестра (раз в неделю)

```bash
# OpenRouter free (18 моделей, capability-поля):
curl -s https://openrouter.ai/api/v1/models | python -c "...фильтр :free..."
# Kilo free + бенчи terminal-bench:
curl -s https://kilo.ai/api/models | python -c "...priceInput==0, benchmarks.kiloBench..."
# Nous Portal каталог:
curl -sL https://hermes-agent.nousresearch.com/docs/api/model-catalog.json
```
Free-пулы вращаются (модели уходят, лимиты меняют): реестр старше месяца не
использовать без перепроверки. Vendor-заявления бенчей не смешивать с
независимыми замерами.

## Pitfalls

- НЕ выбирать модель по бесплатности. 1.1% terminal-bench (cobuddy) — это
  не модель, а генератор огорчений.
- НЕ верить vendor-бенчам поверх независимых: laguna 70.2% (vendor, TB2.1)
  против 31% (kilo, своя версия) — обе правды, но сравнивать их нельзя.
- nemotron-ultra ПРИВЛЕКАТЕЛЕН размером (550B) и контекстом (1M), но код
  пишет хуже всех топовых free (19.1% tb). Не суй его в код-задачи из-за
  громкого имени.
- НЕ отправлять в zcode гигантские промпты без нужды — подписка горит от
  токенов, не от числа запросов.
- codex-данные Jira/Confluence не отдаёт — встраивать в файл.
- Скоринг по первому сообщению задачи; выросла задача — новая точка делегации.
