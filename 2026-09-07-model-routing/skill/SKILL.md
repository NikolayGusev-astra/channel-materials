# model-routing — автовыбор модели под задачу

Цель: жечь платные лимиты (codex sol/terra, zcode glm-5.3) только там, где
они нужны; рутину — на luna/flash/free. Паттерн взят у oh-my-hermes
(`omh coding complexity` + category chains), портирован без их рантайма.

## 1. Инвентарь провайдеров (актуально 2026-09)

| Провайдер | Модели | Лимиты и их характер |
|---|---|---|
| **codex** (GPT Plus, `codex exec -m`) | `gpt-5.6-sol` (frontier), `gpt-5.6-terra` (balanced), `gpt-5.6-luna` (fast/cheap) | Дневной кап на ВЕСЬ аккаунт: «usage limit» убивает все 3 модели сразу — смена модели внутри codex не лечит, уходи на другой провайдер. Всегда явный `-m`, `gpt-4o` НЕ использовать |
| **zcode** (Z.AI coding-plan, anthropic-эндпоинт) | `glm-5.3`, `glm-flash` | Подписочные, восстанавливаются в скользящем окне; при истощении — следующее звено цепочки |
| **nous** (inference-api.nousresearch.com через kilo) | бесплатные Hermes-модели | Free-tier: очереди, скорость нестабильна. ⚠️ Домен НЕ пинить на direct/РФ-узел — ломает LLM (уже ломали) |
| **openrouter** | пул `:free`-моделей | Типовые free-лимиты: ~20 req/min и дневной кап (порядок: десятки запросов/день, выше при балансе ≥$10). Проверяй актуальные у провайдера; для интерактивных длинных прогонов не годится |

**Ключевое правило цепочек:** лимиты у каждого провайдера СВОИ, поэтому
fallback-цепочка обязана диверсифицировать провайдеров, а не модели одного
провайдера. Три бесплатные модели openrouter подряд = три удара в один
дневной лимит.

## 2. Скоринг запроса (детерминированный, без LLM)

Суммируй сигналы:

| Сигнал | Вес | Триггеры |
|---|---|---|
| `subtasks_many` | +4 | «разбей», план из 3+ задач, фаза ТЗ |
| `exhaustive_search` | +4 | «найди все», «каждое вхождение», «все usages» |
| `architecture_keywords` | +3 | архитектура, ADR, схема, миграция схемы БД |
| `impact_system_wide` | +3 | «весь пайплайн», прод, все репо, все ноды |
| `risk_keywords` | +2 | прод, безопасность, деньги, необратимо |
| `debugging_keywords` | +2 | падает, 429, race, утечка, репликация |
| `fanout_intent` | +2 | «распараллель», субагенты, fan-out |
| `cross_file` | +2 | правки в 3+ файлах / нескольких модулях |
| `message_length` | +1/+2 | >1 абзаца / >3 абзацев |
| `routed_skill_class` | +1/+2 | запрос идёт через /cursor аудит-скиллы |
| `simple_request` | **−2** | однострочник, опечатка, «переименуй», вопрос |

Пороги: **0–2 → quick · 3–5 → standard · 6–9 → deep · 10+ → architect/ultrabrain**
(architect если есть architecture_keywords, иначе ultrabrain).

## 3. Цепочки (primary → secondary → tertiary)

| Категория | Тип задач | Цепочка |
|---|---|---|
| **quick** | однострочники, ренеймы, форматы, короткие вопросы | `zcode/glm-flash` → `codex/luna` → `nous/free` |
| **standard** | обычный код 1–2 файла, багфиксы, скрипты | `zcode/glm-5.3` → `codex/luna` → `codex/terra` |
| **deep** | многофайловые правки, диагностика, миграции | `codex/terra` → `zcode/glm-5.3` → `codex/sol` |
| **architect** | архитектура, ADR, ревью дизайна, security-аудит | `codex/sol` → `zcode/glm-5.3` → `codex/terra` |
| **writing** | доки, проза, посты, резюме, переводы | `nous/free` → `openrouter/:free` → `zcode/glm-5.3` |
| **ultrabrain** | тяжелейший анализ, не решается двумя звеньями | `codex/sol` (effort xhigh) → `codex/terra` → стоп и спросить юзера |

## 4. Правила переключения по цепочке

1. **Макс. 2 звена подряд у одного провайдера** (codex luna → terra — ок;
   luna → terra → sol при аккаунт-капе бессмысленно).
2. **codex «usage limit» = кап аккаунта** → все codex-звенья выпадают разом,
   прыжок на zcode/free, а не на другую модель codex.
3. **429/limit на free-модели** → следующее звено, НЕ ретрай той же модели;
   ретрай той же — только после сброса окна.
4. **Free-звенья**: в интерактивных задачах — последними (медленно); в
   writing/batch — первыми (экономия главнее скорости).
5. **Явное указание юзера** («сделай на sol») перекрывает скоринг целиком.
6. После каждого переключения — лог (п.6), чтобы видеть реальный расход.

## 5. Точка интеграции

- Перед каждым `delegate_task` с codex/zcode: скоринг → категория → голова
  цепочки → `codex exec -m <модель>` (всегда явно) или zcode-вызов.
- `/cursor` роутит сюда при вопросах «какой моделью», «выбери модель» и
  перед воркфлоу, где нужен `codex exec`.
- Скоринг занимает секунды и делается в голове/в тексте — НЕ заводить ради
  него субагента.

## 6. Лог маршрутов

Append-only JSONL: `~/.hermes/model-routing-log.jsonl`
`{"ts":"...","task_class":"deep","provider":"codex","model":"gpt-5.6-terra","outcome":"ok|limit|fallback"}`
Раз в неделю глазами: доля sol/terra-звонков должна падать. Файл маленький
(строка на вызов), в чистке не нуждается.

## Pitfalls

- НЕ хардкодить «glm-5.3 всегда лучше free» — free-пул openrouter меняется,
  раз в неделю глянь, что там живо.
- НЕ отправлять в zcode задачи с гигантскими промптами (встраиваемые данные)
  без нужды — подписочный лимит сгорает на токенах, не на числе запросов.
- Скоринг по ПЕРВОМУ сообщению задачи; внутри длинной сессии категория не
  повышается задним числом — если задача выросла, это новое решение в новой
  точке делегации.
- Данные для Jira/Confluence codex НЕ отдаёт — встраивай в файл (standing rule).
