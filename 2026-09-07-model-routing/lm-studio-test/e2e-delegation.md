# E2E delegation test: локальный оркестратор vs free-облачный

**Date:** 2026-09-08 (ночь)
**Вопрос:** реально ли субагенты вызываются из маленьких моделей, или нужен отдельный python-харнесс на каждый тип задачи.
**Ответ:** не нужен. Обе точки вызова работают через нативный tool-calling.

## Вариант А: granite-4.1-3b локально (LM Studio)

Нативный tool-call через `127.0.0.1:1234/v1/chat/completions` с инструментами
`delegate_task` и `answer_self`, system = правила скоринга model-routing.

| Категория | Вызов | model_hint | Время |
|---|---|---|---|
| quick | `answer_self{"answer":"buffer"}` | — | 13.3s (первый, с прогревом) |
| standard | `delegate_task` | deep | 1.0s |
| deep | `delegate_task` | deep | 6.8s |
| architect | `delegate_task` | **architect** | 17.0s |

Все 4 через `finish_reason: tool_calls`. Выбор инструмента и категории верный 4/4:
простая задача осталась себе, все остальные ушли в делегацию с корректной подсказкой модели.

**Нюанс:** на русском тексте goal-аргумент granite 3B искажает ("распарлены загоды").
Структура вызова при этом сохраняется. В реальной связке goal должен браться из
оригинального сообщения пользователя, а не пересказываться моделью диспетчера.
Практика Hermes делает именно так.

## Вариант Б: stepfun/step-3.7-flash:free в живом Hermes

Полный e2e: `hermes -m "stepfun/step-3.7-flash:free" --provider kilo -z "<задача>"`.
Сессия `20260908_040822_434879`, транскрипт в session-exports.

Цикл:
1. step-3.7 получила задачу "найди все deprecated API и предложи миграцию"
2. Сама прогрела контекст: find по каталогу, два skill_view (deprecation-and-migration, codebase-audit-methodology)
3. **Нативно вызвала delegate_task** с action=spawn, полным context (реестр из 4 файлов) и goal
4. Субагент отработал: 195s, 14 API-вызовов, 685K входных токенов, **cost_usd = 0.0**
5. Субагент реально правил файлы: send_tg.py (curl → requests+retry), download-bonus4-bundle.py (urllib → requests+backoff), создал model-catalog.json, вынес CHAINS в каталог
6. Оркестратор вернула отчёт юзеру с "Исполнитель: codex через delegate_task"

Верификация родителем: py_compile всех трёх .py - OK; route.py с новым каталогом выдаёт корректный роутинг.

Механизм делегации работает из обеих точек без python-обвязок. Рабочая связка для экономии:
granite-3b локально как диспетчер выбора категории, исполнение через delegate_task
на free/платных моделях по цепочке. Либо полностью облачный вариант: step-3.7:free
как оркестратор сессии, когда сеть стабильна и дневной лимит free не исчерпан.
